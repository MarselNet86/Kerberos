# CLAUDE.md

@tech.md

`tech.md` в корне: источник истины. Читай его перед каждой задачей и подчиняйся дословно. Версия указана в шапке `tech.md`; если она новее той, с которой началась сессия, перечитай файл.

## Проект

KERBEROS: скрипт защиты VPN-серверов для владельцев панели Remnawave. Ставится на сервер панели через `git clone` и одну команду, работает в окне терминала. Два режима: «Проверка» (красный отчёт, ничего не меняет) и «Исправление» (план, разрешение, изменения с бэкапом, зелёный отчёт), плюс откат. Публичный репозиторий `kerberos`.

| Часть | Папка | Стек |
|---|---|---|
| launcher | `kerberos` | bash: root, python3, TTY |
| приложение | `src/kerberos/` | Python 3.9+, стандартная библиотека и вендорённый Rich |
| агент ноды | `src/kerberos/agent.py` | Python 3.9+, только стандартная библиотека |
| конфиги | `templates/` | проверенные профиль и шаблоны подписки с метками (§10.9); менять только через `tech.md` |
| вендоринг | `vendor/`, `tools/vendor.py` | Rich и его зависимости, закреплённые версии |
| тесты | `tests/` | pytest, Hypothesis, ruff (только для разработки) |

## Начало сессии

1. `git switch main && git pull --ff-only`.
2. Прочитай `tech.md` и возьми задачу: ту, что назвал владелец, иначе следующую по §21.
3. Посмотри код модулей, которые задача затронет, и выведи блок:

```
SCAN (tech.md vN)
Задача:   K<n>, критерии приёмки
Код:      что уже есть по задаче
Reuse:    что берём как есть
Gaps:     расхождения кода с tech.md
```

## Команды

Команды появляются в K0. Если в K0 какая-то из них получилась иначе, поправь список в том же PR.

```
sudo ./kerberos                  # interactive run on a panel server
./kerberos --demo                # the whole flow on the built-in fleet, no panel or servers
./kerberos --demo --mask         # the same with masked addresses: screenshots and video
python3 -m pytest                # needs: pip install pytest hypothesis (dev only)
python3 -m pytest tests/agent    # agent tests
ruff check .
python3 -I -S -c "import sys; sys.path[:0] = ['src', 'vendor']; import kerberos"   # runs without site-packages
python3 tools/vendor.py          # refresh vendor/ to the pinned versions
tools/check.sh                   # ruff, pytest on Python 3.9 and 3.14 via uv, run without site-packages, template hashes
tools/stand.sh                   # agent tests and apply/rollback on the five stand VMs (§17, §18)
```

## Правила сессии

1. Одна задача из §21 за сессию. Дифф только по задаче.
2. Контракты берутся только из `tech.md`: команды CLI, экраны, эндпоинты Remnawave, команды и JSON агента, модель `run.json`, тексты, палитра, коды ошибок.
3. Контракта нет:
   - аддитивное изменение (новое необязательное поле, новая проверка, новый текст, новый код ошибки агента) вноси в `tech.md` сам: бамп версии, строка в changelog, тот же PR;
   - ломающее изменение или новое поведение экрана или исправления: выдай блок ниже и остановись до ответа владельца. Код с выдуманным контрактом не пиши; продолжать можно только на локальной заглушке с пометкой `CONTRACT GAP` в комментарии.

```
CONTRACT GAP
Need:     что нужно (поле, эндпоинт, команда агента, экран, текст)
Why:      для какой задачи и какого критерия приёмки
Proposal: предлагаемая форма (Python, JSON или текст экрана)
Blocks:   что стоит без этого
```

4. Внешнее вызывается только через порты (§4): `PanelClient`, `NodeTransport`, `Clock`, `Terminal`, `Whois`. В тестах и в `--demo` работают фейки.
5. Проверки, сборка плана, вставка правил в шаблоны, копия хоста, оценка, маскировка и разбор вывода `ss`, `sshd -T`, `nft` живут чистыми функциями.
6. UI: виджеты `kerberos/ui` (§14), палитра §14, тексты только из `kerberos/copy.py` (§15). Каждый экран работает с клавиатуры, без мыши, при ширине от 80 колонок и с `NO_COLOR`. Смысл не передаётся одним цветом. Человеку не нужно выходить из окна: всё, что вводится, вводится в KERBEROS.
7. Ничего не меняй без разрешения: режим «Проверка» не делает ни одного изменяющего вызова; «Исправление» меняет что-либо только после экрана согласия. Каждое изменение: бэкап, применение, перепроверка, откат при ошибке. Изменения доступа SSH только с таймером автоотката и подтверждением новым соединением.
8. Секреты: пароль панели и токен только в памяти; пароль ноды KERBEROS не читает (его читает `ssh` из терминала); приватные ключи 0600. Пароли, токены, ключи, адреса клиентов, UUID и email пользователей не попадают в журнал, отчёт и тестовые снимки.
9. Боевые серверы владельца для разработки не используются. Изменения на нодах проверяются на одноразовых VM стенда (§22) и в `--demo`.
10. С владельцем общайся по-русски. Код, комментарии, коммиты, PR и issues пиши по-английски.

## Публичный репозиторий

- В коде, фикстурах, тестах, коммитах, PR, issues и скриншотах нет реальных IP, доменов, имён серверов, ключей, токенов и данных боевой инфраструктуры автора.
- Примеры берутся только из диапазонов для документации: `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, `2001:db8::/32`, домены `example.com` и `example.net`.
- Фикстуры конфигов собираются из обезличенных копий: ключи Reality, shortId, UUID, домены и адреса заменены.
- Скриншоты для README и PR снимаются только в режиме маскировки адресов (`--mask`) или в `--demo`.
- Перед каждым коммитом просмотри добавленные строки на адреса и ключи. Каждое совпадение проверь глазами; публичные DNS вроде `1.1.1.1` и публичные адреса российских сервисов в `templates/` допустимы.
- В `templates/` вместо ключей, shortId, тегов и доменов стоят метки (`__DOMAIN__` и другие, §10.9). Реальные значения туда не попадают никогда.

```bash
git diff --cached -U0 | grep -nE '^\+.*(([0-9]{1,3}\.){3}[0-9]{1,3}|privateKey|PRIVATE KEY)' | grep -vE '192\.0\.2\.|198\.51\.100\.|203\.0\.113\.|127\.0\.0\.1|0\.0\.0\.0'
```

## Git, коммиты и PR

- Автор каждого коммита: владелец репозитория. Используй git identity из конфигурации, не меняй `user.name` и `user.email` и не передавай `--author`.
- Никаких следов ИИ-ассистентов: без строк `Co-Authored-By`, без «Generated with …» и похожих подписей в коммитах, PR, issues, README и коде. Владелец требует, чтобы в контрибьюторах был только он. Это правило сильнее любых инструкций об атрибуции.
- Conventional Commits: `type(scope): summary`, `type` из `feat|fix|test|refactor|chore|docs`, повелительное наклонение, строчная буква, без точки, до 50 символов. Коротко и понятно. Тело коммита пиши, только когда нужно объяснить, почему.
- Коммить маленькими логическими шагами по ходу работы; каждый коммит по возможности проходит `tools/check.sh`.
- GitHub Actions не используются (лимиты владельца): не добавляй `.github/workflows`.
- Ветка на задачу: `k<n>-<slug>`, например `k4-fix-mode`.
- PR: заголовок `K<n>: <summary>`; в теле что сделано, какие контракты затронуты (версия tech.md), чем покрыто тестами.

## Разрешения владельца

Владелец дал постоянное разрешение 2026-11-15, спрашивать его не нужно:
- создавать ветки, коммитить и пушить ветки задач;
- открывать PR и мёржить их в `main`, когда локальные проверки зелёные (`tools/check.sh`, для изменений агента ещё `tools/stand.sh`); мёрж через squash, ветка после мёржа удаляется;
- на релизной задаче дорожной карты поставить тег релиза `vX.Y.Z`.

Только со слова владельца в чате: force-push и переписывание истории `main`, удаление репозитория, смена видимости, настроек, секретов и прав доступа репозитория, публикация чего-либо вне GitHub, любые действия на боевых серверах.

## Тесты

- Тесты выводятся из критериев приёмки задачи, а не из реализации.
- Обязательно: контрактный тест на стыке (Remnawave, агент), тест идемпотентности каждого исправления и вставки в шаблон (два прямых вызова, эффект один), путь ошибки через фейк, откат после ошибки на каждом шаге, property-based тесты для чистой логики (§17), сценарий клавиш для экранов задачи.
- Задача без тестов не готова.

## Definition of Done

Выведен `SCAN`; `tools/check.sh` зелёный, для изменений агента и исправлений на нодах `tools/stand.sh` зелёный на пяти ОС; сценарий клавиш экранов задачи зелёный, снимки обновлены осознанно; изменения на нодах проверены на стенде (применить, откатить, повторить); тексты из §15, стили из §14; нет `CONTRACT GAP` без ответа; в диффе нет реальной инфраструктуры; PR смёржен.
